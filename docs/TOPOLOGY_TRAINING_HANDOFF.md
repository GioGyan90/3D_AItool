## 2. 最高优先级原则：训练案例不固化为预设

**每轮练习都应是临时工作内容，而不是产品功能的一部分。**

- **禁止**因为完成一个练习就向首页、默认模板、基础形菜单、预设下拉框、右侧常驻按钮新增“练习模型名”。
- **禁止**为某个练习写死模型专用的顶点坐标、路径、形状规则和特殊判断到通用编辑器逻辑内。
- 可通过当前场景中的临时草稿、导入/导出的 `.shape3d.json`、控制网格 JSON、GLB、截图和 QA 产物来保存练习。测试 fixture / 临时样例文件与**面向用户的内置预设**是两回事。
- 只有某项方法已经被多个不同模型验证可复用，才将**抽象后的通用操作**（例如刀切、环线终止、吸附、焊接、桥接）加入工具。不要把练习造型本身加入快捷预设。
- 旧魔方属于回归测试样例：独立首页入口已在 PR #6 移除；仅在**布线建模 → 布线 → 默认折叠的「快捷示例 · 3×3 魔方环切」**保留，不再扩散成独立首页入口。新练习不需要再复制这种永久示例机制。

## 3. 目前可用的主要能力

- 基础立方体、球体、圆柱体转换为可编辑控制网格；立方体真实四边面连续环切
- 局部四边面切割、面内插、沿面法线挤出、X=0 半模镜像并焊接中心线
- 顶点拖动、精确坐标、X/Y/Z 对称移动；选顶点、选边、单面或 Shift 多选面
- 同平面 / 同色批选、逐面涂色、模型 JSON 和 GLB 导出
- 撤销/重做、应用到场景、保存项目并重开；正交多机位和 3D 观察、X-Ray、显示布线/成品预览
- UI 已分为布线 / 塑形 / 配色 / 检查；右侧选择摘要紧凑、精确坐标可展开，工具页签固定且参数单独滚动；可展开工具区，窗口大小变动会重新适配摄像机

**已知边界：** 真正的自由刀切、边倒角、边桥接、多面协同挤出尚未作为通用操作完整交付；连续环切主要针对四边面；局部切割有可能产生三角面 / 多边面；不应声称已有完整 Blender 级的工具链。

## 4. 每轮训练的工作方法（严格遵循）

1. **规划造型**：对用户给定参考图先拆解主要体块、轮廓、正/侧/背面特征，定义最少必要控制点、边与面，并确定从哪个基础形出发。先明确为何需要某条线，而不是平均细分。
2. **制定操作序列**：写出本轮实际使用的现有工具；缺工具时明确指出卡点、输入/输出与预期拓扑，先实现通用操作及单元测试。
3. **渐进建模**：少量步骤分批修改；每次变更都保证顶点索引、共享边和面绕序明确。保留可撤销历史及临时保存版本，不要一次生成大量随机/规则网格。
4. **真实浏览器观察**：在网页 WebGL 中从正、侧、背、俯、仰和 3/4 多角度截图。**自己查看实际截图**，检查轮廓、凹凸、边线流向、法线、接缝、穿模、背面和未预期的空洞，发现问题就修一轮。
5. **拓扑 QA**：验证边引用、重复/孤立顶点、T 型接缝、非流形边、面翻转、三角化、变形后的对称关系；如果练习允许开放表面，明确记录边界，不误判为必须封闭。
6. **交互 QA**：测试选中状态、拖动、吸附/对称、撤销重做、工具切换、参数输入、应用场景、保存重开和导出。桌面、矮窗口与移动端检查可见性及拖动能力。
7. **记录与发布**：报告本轮模型做到了哪里、哪些工具被扩展、截图结果及尚未解决的缺陷。按已授权流程提交、合并、构建和 Pages 发布；必须核对 CI 与实际部署，不假定“提交代码=上线”。

**不采用**“看不懂顶点空间关系 → 再加大量规则面数 → 用密网格掩盖轮廓错误”的路径。

## 5. 工具完善的优先方向

按训练中实际遇到的阻碍决定，不预先堆功能：
- **局部刀切与走线终止**：任意边选点、连续路径、局部闭合，尽量维持可理解的四边形布线，避免悬空 T 点
- **选择与编辑**：边环/边圈选、局部区域选择、多选状态、吸附、顶点焊接、合并与断开
- **精确塑形**：拖动轴锁、镜像中心约束、软选择/比例影响、可调边倒角、桥接相邻边界
- **几何反馈**：明显的边/顶点/面选中态、法线及非流形可视化、撤销前后的差异展示、参数预览后确认
- **界面和效率**：高频操作就近、其余折叠，不要新增练习专用按钮；小窗口仍能看到画布和可滚动的全部参数

## 6. 训练成果如何留档

每轮可在 `docs/training/` 下记录方法总结或生成**用户指定的**导出文件；自动化 fixtures 可放在 `tests/fixtures/`，截图放在 CI artifact 或临时工作目录。建议训练日志结构：`目标与参考 → 起始形状和控制面数 → 操作顺序 → 发现的问题 → 修复的通用工具 → 多机位截图 → QA/发布状态 → 下一轮建议`。

**不要自动注册到**：`src/App.tsx` 首页按钮、默认 `INITIAL_NODES`、内置模型预设列表或启动时自动加载场景。确需新增正式产品预设，必须由用户另行明确要求。

## 7. 交付和授权

正常修改、提交、合并、发布已获用户授权，无须反复确认。每轮应提供对应 PR/commit、在线入口、实测截图或 Actions 验证记录，并诚实指出没有覆盖的交互。最后只保留**真正可复用的工具能力、文档与必要回归测试**，而不是一堆永久练习模型。
