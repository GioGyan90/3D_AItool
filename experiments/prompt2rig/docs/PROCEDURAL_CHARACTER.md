# 自建人物：截面灰模 v1

按用户提供的 `LOW_POLY_CHARACTER_WORKFLOW.md`，先研究比例和体积，再看动作变形。当前默认人物全部由独立编写的截面参数生成，没有导入现成人物，也没有从参考 GLB 复制顶点。原方法论中的参考模型、拟合数据和轮廓分数未提供，本项目不沿用其精度数字。

## 本轮实现

- 以约 6.5 头身、1.785 米总高组织头、胸、腹、骨盆及四肢；先做素灰，无五官、发型、衣服或贴图。
- 用有序椭圆截面圈控制体积，在肩、肘、髋、膝、踝等位置调整半径与偏移；相邻圈连接后转三角形，首尾封口。
- 单侧建模后镜像，反转镜像三角形绕序。29 个封口零件：头、颈、胸、腹、骨盆，以及每侧上臂、前臂、大腿、小腿、脚、手掌、五指、耳朵。
- 共 2,572 个三角面、1,344 个顶点、29 个网格、52 根骨骼（含手指骨）。动作方案目前驱动身体主要关节，尚不生成精细手指动作。
- 肘和膝的相邻零件使用一致的接缝截面与权重，测试动作中保持接合；肩髋采用内部搭接，仍可继续雕琢。

## 在网页检查

默认进入灰模 A 姿态。正面、侧面、背面使用正交投影，后斜和斜侧用于检查体积。可切换零件配色、线框、单个零件及拆解距离；单件观察只调整相机，不修改模型原点。

“动作预览”恢复整个人物并播放动作。现有提示词、聊天 JSON 方案、导出流程继续适用。现成人物 GLB 导入折叠为后备方案。

完整人物导出会临时取消拆解和单件隐藏，导出后恢复检查状态。单件导出为无蒙皮静态网格，保持原始 **T 姿态装配坐标**，不把画面上的拆解位移或相机居中写入文件。静态整个人物样本见 [procedural_character_v1.glb](../samples/procedural_character_v1.glb)。

## 验证与边界

`npm test` 共 16 项通过，其中新增 5 项覆盖封口拓扑、镜像、蒙皮权重、动作接缝、拆解状态导出及单件坐标。每件网格的无向边恰好连接两个面，边方向相反，无退化三角形，封闭体积为正。详细数据见 [procedural-validation.json](procedural-validation.json)。

重新生成报告和静态 GLB：

```sh
node --experimental-loader ./tests/vendor-loader.mjs tools/verify-procedural-character.mjs
```

这些验证保证零件自身封口，不代表 29 件合并后是连续焊接的单一人体。没有穷尽自相交、极限动作穿插或肩髋曲面的美术检查；目前仍是第一轮低模基础体，不是完成的游戏角色。浏览器检查采用同一网格与蒙皮的 Canvas 回退路径，当前环境无法验证实际 WebGL 渲染。

下一轮先根据多视角轮廓反馈修正肩颈、胸背、骨盆和四肢比例，再考虑连续拓扑、面部、服装与更精细的关节权重。只有自建方案效果持续不佳时，再比较现成模型。
