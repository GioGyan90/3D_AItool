## 5. 背心、瑜伽裤与运动鞋的关键做法

### 背心

- 基于实际女性基础体拟合胸背、肩带、领口、袖窿和下摆；肩带要有合理宽度、厚度和前后衔接。
- **肩膀、上臂、腋下、领口与袖窿露出的皮肤必须存在。** 不能照搬少年短袖 T 恤的删面遮罩，否则肩臂会缺块。按新背心的实际覆盖范围重算身体遮罩。
- 先做连续拓扑、权重与折角法线，再按语义分件。不要独立减面新接缝，或用长三角面把领口直接拉到腋窝。
- 确定被背心遮挡的身体面从装配体实际删掉；边界保留适当衣内重叠，未裁切源数据另存。

### 瑜伽裤与腰部衔接

- 以实际腰胯、裆部、臀腿拓扑拟合；控制必要松量，保留弯髋、屈膝和大腿前摆的变形环线。
- 删除确定藏在不透明裤子里的重复腿部皮肤，保留实际外露的腰部 / 脚踝；不要既删去外露皮肤又留下衣内重复身体。
- **背心遮住裤腰时，优先内收遮盖部分的裤腰，再用短过渡和协调权重衔接。** 保持认可的背心外轮廓，不默认把上衣撑成宽松桶形。
- 不让裤腰调整波及可见臀腿。检查衣物相互之间的穿插；单件法线正常不能证明上衣与裤子没有穿模。
- 重点检查裆部夹面、臀部拉扯、膝窝折叠、腰带漂浮与大腿交叉。低模需要的局部补面与减面分别统计，不为固定减面比例牺牲变形。

### 鞋与头发

- 鞋按实际脚型拟合，左右鞋 / 鞋底跟随对应 Foot；脚尖朝向、踝关节和鞋底落地高度单独核对。
- 头发按选定基础体拟合，检查正侧背和前后俯视；不能为了藏穿模把可见侧后发整体剃平。
- 第一版可用稳定的束发 / 短发。不必为本轮引入头发动力学；若加辅助骨，其动作也需进入导出。

## 6. 跑步：必须新增真实动作及专门检查

当前 `public/lab/motions.js` 只有 `wave`、`victory`、`billiards` 三段测试，**还没有跑步**。

建议先完成一个容易检查的循环跑步 take：可用约 4 秒的原地循环验证体态与步态，之后再根据展示需要决定是否加入前进位移。原地 / 位移是制作选择，用户未明确限定。

动作要实际作用于模型：

- 左右腿交替前摆、后蹬与屈膝回收，双腿相差半周期；对侧手臂协同摆动，骨盆、躯干与肩部有克制的反向变化。
- 包含接触、承重、蹬离、腾空和回收，检查最大屈髋、最大屈膝、前后摆臂和循环接缝；不能只有字幕、头部或根节点在动。
- 手肘保持自然弯曲，手腕稳定。保留掌面与前臂的解剖校正，但**不要把挥手时“掌心朝前”的要求强制套到跑步**；跑步掌面随自然摆臂变化，避免异常翻腕和绕轴转圈。
- 检查实际脚底与地面接触。当前地面修正不是完整足部 IK，也不会自动解决滑步；位移速度、步幅、步频与支撑相位需协调。原地跑按约定的虚拟地面速度评估，不与带 root 位移的结果混淆。
- `motion-plan v1` 的整段时长限制是 1–20 秒、2–64 个关键姿态；不要为小于 1 秒的单个步态周期硬改协议，可在有效总时长内重复若干完整周期。

统一协议仍为：标准 T 姿势，人物左侧 +X、向上 +Y、向前 +Z；局部 XYZ 欧拉角用度，root 用米。方案走 `planToTake → applyRetarget / retargetTake → GLB`。不要把目标 A 姿势的局部角直接当成标准 T 姿势角度。

恢复真实绑定姿势后核对单位、左右、脚链与实际指根。新人物不能照抄少年的肩部节律参数或西装长袖辅助骨；需要辅助骨时单独验证，并写入烘焙导出轨道。骨骼数量按实际结构统计，不硬凑 52 或 56。

网页 API 默认 OpenAI，支持用户填写兼容服务、模型和 Key；网页不能借用聊天凭据。新窗口可直接制作 / 导入动作 JSON，不需要为这次试验先发起付费 API 调用，也不需要改动已有 API 设置。

## 8. 验证与已知陷阱

既有基线：少年与西装各有 154 个服装姿态采样、903 个导出手臂旋转采样；少年的衣裤间距还有单独报告。西装服装最小法线对齐约 0.14785、最小面积比约 0.10898。详细结果在现有 `docs/*VALIDATION.json`。

下一轮必须为女性与跑步新增验证，不能复用这些数字宣布通过：

1. 核对来源许可、完整基础体、成年比例、左右对称、有限顶点 / 法线 / UV、有效骨索引、归一化权重和正确脚链。
2. 检查背心肩带、袖窿、外露肩腋，以及腰胯、裆部、臀部、膝窝和鞋底；对真实新服装采样法线、面积与层间穿插。
3. 对**实际跑步动作**做整段采样，另查关键接触 / 极值时刻与首尾接缝；对烘焙后的动画检查腕、前臂、膝与脚踝的连续性。
4. 完整导出 GLB 并重新加载，用 AnimationMixer 比对实际姿态与顶点；辅助骨、材质与贴图保留，检查视图状态不得污染导出。
5. 至少覆盖正、侧、背、四分之三、斜前俯视、斜后俯视、灰模和真实材质，以及实际跑步；发现问题后修正再复查。

现有检查器不能原封不动当成新任务验收：

- `check-teen-deformation.mjs --sweep` 的动作与时长硬编码为旧三段；服装名称 / 预设也只认识现有两套。仅添加跑步按钮或把新 GLB 路径传进去，不等于检查了跑步。
- `check-teen-arms.mjs` 遍历 `MOTIONS`。若向这个数组加入跑步，旧测试中 903 个采样等断言也会受影响；应明确扩展动作范围与报告，或为新跑步单独安排测试输入，不删旧覆盖来凑通过。
- `check-teen-waist.mjs` 假设少年服装命名和 `shirtConstruction.hemY`，不能直接当女性背心 / 瑜伽裤检查器。新增检查需断言选中真实服装、采样数量大于零且结果有限，避免空检查。
